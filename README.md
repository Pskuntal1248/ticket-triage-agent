# ticket-triage

A support ticket triage agent for the Gravity platform (LangGraph).
It classifies a ticket with the model, applies fixed refund rules in plain Python, and drafts or sends the reply.

| Refund amount | What happens |
| --- | --- |
| not a refund request | reply drafted |
| under $50 | recommended by pilot policy, reply drafted; no refund issued |
| $50 to $200 | under-review reply sent after message approval (gated `gmail.send`); rejection, timeout or tool failure attempts a holding draft |
| over $200 | Slack escalation attempted (gated `slack.send`, optional channel); draft reports whether delivery succeeded |

Gravity has no refund tool, so the agent records the refund as a recommendation; it does not move money.
The refund amount must appear in the ticket text, so a number the model makes up is dropped or corrected. If the model returns no amount but the ticket has exactly one explicit USD amount, that amount is used (1.0.2).

## Layout

- `manifest.yaml` Gravity manifest (tools: gmail.draft, gmail.send, slack.send; approvals on both sends)
- `src/agent.py` entrypoint (`graph`), `src/relayg/` the adapted code
- `tests/` unit tests (fake tools, no gateway needed): `pytest tests`

## Build

```bash
uv tool install gravity-cli
gravity validate && gravity build   # push needs `gravity login`
```

### Limits before a real gateway run

This is a pilot, not a validated company refund policy. Dollar thresholds are
RelayG's sample rules. The agent never contacts a billing system and never moves
money. Approval of a Gmail message does not authorize a refund. An explicit
request still needs human review for eligibility and customer identity.

Local unit tests and validate/build cannot verify real tool arguments/results,
model availability/structured output, account permissions, or durable hosted
approval resume. The SDK branch is tested with a fake module, not the hosted SDK.
The hosted SDK must preserve approval control signals outside ordinary Exception;
that remains to be checked on Gravity. Do not treat the zip as production-verified.

No output renderer/corpus is declared: this is a result card plus tool actions,
not a document/report generator. Adapters, scheduling and cross-thread memory
are optional and intentionally absent.
